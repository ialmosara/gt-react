# Global Tassels — React Website

A React + Vite rewrite of the full Global Tassels site, built from the site blueprint: Home, About, Our Ecosystem
(overview + GT Academy, GT Foundation, GT Institute), Where We Work (overview + a data-driven template for all six
countries), Leadership & Governance, Our Impact, News & Events, the Founder's Gala, and Give.

Same design system as the original single-page prototype (purple/gold palette, Libre Caslon Display + Public
Sans), now split into reusable components and routed with React Router so it behaves like a real multi-page site.

## Getting started

Requires Node 18+ and npm.

```bash
npm install
npm run dev       # starts a local dev server, usually http://localhost:5173
```

To build for production:

```bash
npm run build      # outputs static files to dist/
npm run preview    # serves the production build locally, to sanity-check it
```

## Accepting payments (Givebutter)

Every "Give Once," "Give Monthly," "Buy Your Ticket," and "Become a Sponsor" button on the Give and Gala pages
goes through `components/DonateButton.jsx`. Unlike the newsletter/Instagram pieces, this needs no serverless
function or secret token — Givebutter's checkout is an embeddable widget that opens a popup right on the page,
so `DonateButton` just loads their script and lets it upgrade the button. No platform fee, and Givebutter
issues IRS-compliant tax receipts automatically, which matters for a 501(c)(3).

**Before it's configured** (`data/givebutter.js` has empty strings), every button quietly falls back to a plain
in-page anchor — nothing looks broken, there's just no working checkout yet.

**One-time setup (Givebutter's side — needs the org's real EIN/501(c)(3) documentation and a bank account for
payouts, so this has to be you):**

1. Create a free account at [givebutter.com](https://givebutter.com) and complete their nonprofit verification.
2. Create **one campaign** for general/recurring giving — Givebutter's own campaign page lets a donor choose
   one-time vs. monthly and enter any amount, so this single campaign covers "Give Once," "Give Monthly," and
   "Sponsor a Student."
3. Create a **second campaign** as a Givebutter *Event* for the Founder's Gala, with ticket types and
   sponsorship tiers (Individual $350, Bronze $500, Silver $1,000, Gold $5,000) configured as options within it
   — not as four separate campaigns.
4. Find your **Account ID** (Account Settings → General) and each campaign's **code** (from its URL or the
   Widget Builder), and fill in `src/data/givebutter.js`:
   ```js
   export const givebutter = {
     accountId: 'xxxxx',
     donateCampaign: 'xxxxx',
     galaCampaign: 'xxxxx',
   };
   ```
5. Commit and deploy. Every donate/ticket button on the site now opens the right Givebutter checkout.

**Worth double-checking:** Givebutter occasionally tweaks their embed script/attributes — `DonateButton.jsx`
uses their standard `givebutter-campaign-button` pattern, but it's worth confirming against the exact snippet
their in-dashboard Widget Builder generates for your account before going live.

## Email list (newsletter signups)

The "Stay connected" form on Home and News & Events (`components/NewsletterForm.jsx`) posts to a Netlify
Function (`netlify/functions/subscribe.js`) that adds the address to a Mailchimp audience. No subscription of
its own — it's free on both sides (Netlify Functions' free tier, Mailchimp's free tier up to ~500 contacts).

**One-time setup:**

1. Create a free [Mailchimp](https://mailchimp.com) account and an Audience (List) for the site.
2. Get your **API key**: Account → Extras → API keys. It looks like `abc123...def-us21` — the `us21` part
   after the dash is your **server prefix**.
3. Get your **Audience/List ID**: Audience → Settings → Audience name and defaults.
4. Deploy this site to Netlify (connects automatically via `netlify.toml`, which also sets the SPA fallback
   redirect the site needs).
5. In the Netlify dashboard: Site configuration → Environment variables, add:
   - `MAILCHIMP_API_KEY`
   - `MAILCHIMP_SERVER_PREFIX` (e.g. `us21`)
   - `MAILCHIMP_LIST_ID`
6. Redeploy. The form now works — submissions are idempotent (resubscribing an existing address just updates
   their status, it won't error).

**Local testing:** copy `.env.example` to `.env`, fill in the three values, then run `netlify dev` (via the
[Netlify CLI](https://docs.netlify.com/cli/get-started/)) instead of `npm run dev` — that serves the function
locally too. Plain `npm run dev` will show the form's built-in error state when it hits the missing endpoint,
which is expected.

**Switching providers:** everything Mailchimp-specific lives in `netlify/functions/subscribe.js` — swapping to
Buttondown, ConvertKit, etc. only means rewriting that one file's API call.

## Instagram photo sync

Rather than a live widget or an always-on backend, photos sync on a schedule: a GitHub Action
(`.github/workflows/sync-instagram.yml`) runs `scripts/sync-instagram.mjs` weekly, which downloads the latest
photos from Instagram, saves them into `public/images/social/`, writes `src/data/socialPhotos.json`, and commits
the result — which triggers a normal Netlify redeploy. No server runs in between syncs, and no subscription is
required anywhere in this pipeline. `components/InstagramFeed.jsx` (currently used in News & Events' Media
section) reads that JSON and renders real photos through the existing `PhotoPlaceholder` component, falling back
to a friendly "coming soon" placeholder grid until the first sync runs.

**One-time setup (all on Meta's side, so this part isn't something I can do for you):**

1. Convert the Instagram account to a **Business or Creator account** and link it to a Facebook Page.
2. Create an app at [developers.facebook.com](https://developers.facebook.com), add the **Instagram Graph API**
   product, and generate a long-lived User Access Token for the account (Meta's docs walk through the OAuth flow
   — it's a one-time manual step, typically via the Graph API Explorer).
3. In the GitHub repo's settings: Settings → Secrets and variables → Actions, add a secret named
   `INSTAGRAM_ACCESS_TOKEN` with that token.

That's it — the workflow will run automatically every Monday, or you can trigger it manually anytime from the
Actions tab ("Run workflow"). To change the cadence, edit the `cron` line in the workflow file.

**Token expiry:** long-lived Instagram tokens last ~60 days and need refreshing before they expire (Meta's
`GET /refresh_access_token?grant_type=ig_refresh_token` endpoint). This isn't automated yet — set yourself a
reminder every ~6–7 weeks to refresh it and update the `INSTAGRAM_ACCESS_TOKEN` secret. Automating that rotation
is a reasonable next step once this is live (it needs a repo-scoped personal access token to let the workflow
update its own secret, which is worth adding deliberately rather than by default).

**Trying it locally:** `INSTAGRAM_ACCESS_TOKEN=xxxx npm run sync:instagram`

## Adding a seventh country

This is the one piece of the blueprint's architecture that's worth calling out: add a new object to the
`countries` array in `src/data/countries.js` (slug, name, summary, stats, programs, impact, stories, gallery) and
it automatically gets its own page at `/where-we-work/<slug>`, plus a card on the `/where-we-work` overview and a
pin on the homepage map. No component changes needed.

## Deploying

This is a client-side-routed single-page app (React Router's `BrowserRouter`). Whatever host you deploy `dist/`
to needs to serve `index.html` for *any* path, not just `/` — otherwise a direct link to, say,
`/where-we-work/kenya` will 404 on refresh.

**Netlify is the assumed target** (`netlify.toml` is already set up with the build command, the SPA fallback
redirect, and the Functions directory the newsletter form needs) — connect the repo at
[app.netlify.com](https://app.netlify.com) and it should just work once the Mailchimp environment variables are
set (see Email list, above). Vercel and most other static hosts work too, but you'd need Vercel's own Functions
setup instead of `netlify/functions/`, and their own SPA-fallback config in place of `netlify.toml`'s redirect.
